## 0. 한 줄 결론

폼 자체는 이미 괜찮고(매입/납품 토글·전화 자동 하이픈·저장·관리자 화면까지 있음 [확인]), **빠진 건 "알림"과 "사진"** 이다. 문의가 홈페이지 전용 Supabase(`inquiries`)에 조용히 쌓이기만 하고 아무 데도 알리지 않아서, **10-15 납품 문의 1건·05-25 매입 문의 2건이 아직 `new`** 로 남아 있다 [확인]. 순서는 **P0 즉시 알림 + 중복·스팸 가드(반나절) → P1 사진 첨부 + 수량·규격 칸(1~2일) → P2 어드민으로 전달해 매입견적서 프리필(0080, 2~3일)**.

## 2. 설계 원칙 [결정]

1. **접수는 홈페이지가, 처리는 어드민이.** 홈페이지 DB `inquiries` 는 "접수 원본"으로 남긴다(저장 실패 없이 가장 가까운 곳). 어드민(bk-steel-admin)에는 **비동기로 전달**해 매입견적서·거래처·유입경로로 이어 붙인다(P2). 전달 실패가 사용자 접수를 막지 않는다.
2. **필수는 이름·연락처 둘뿐.** 현장소장은 폰으로 30초 안에 보내야 한다. 나머지는 전부 선택이되, **사진 한 장이 글 열 줄을 대신**하므로 사진 칸을 가장 눈에 띄게.
3. **사진은 비공개 저장.** 남의 현장 사진이다. 공개 URL(Cloudinary unsigned)이 아니라 홈페이지 Supabase **Storage private 버킷** + 서명 URL. 어드민으로 넘길 땐 어드민 버킷에 다시 올려 영구 보관(홈페이지 쪽 의존 제거).
4. **B계좌·책 정보는 홈페이지 어디에도 없다.** 전달 API 페이로드에도 book 을 두지 않는다(어드민에서 사장이 고른다).

## 3. 폼 설계 (P1)

### 3.1 매입 문의 (기본 선택)

| 순서 | 칸 | 입력 | 필수 | 비고 |
|---|---|---|---|---|
| 1 | 문의 구분 | 매입 / 납품 토글 | ✓ | 현행 유지. `#contact?type=매입` 딥링크 유지 |
| 2 | **사진** | `<input type="file" accept="image/*" multiple capture="environment">` 최대 **6장**. 고르면 즉시 썸네일, 각 장 ✕ 로 빼기 | — | "철근 더미·태그·길이가 보이게 찍어 주세요" 안내 + 예시 썸네일 1장. 클라이언트에서 **긴 변 1600px JPEG 로 축소**(bk-steel-admin `lib/image-compress.ts` 복사) → 장당 200~400KB |
| 3 | 성함/업체명 | text | ✓ | 현행 |
| 4 | 연락처 | tel, 자동 하이픈 | ✓ | 현행 |
| 5 | 현장/지역 | text + `datalist`(경주·포항·울산·대구·부산·경남·경북·전북…) | — | 현행 + 자동완성 |
| 6 | **대략 수량** | text(`inputMode=decimal`) + 단위 토글 **톤 / 본(개)** | — | "모르면 비워 두셔도 됩니다" |
| 7 | **규격·길이** | text | — | placeholder "예: D22 9m 34본, D13 8m 67본" (실제 문의 문장 그대로) |
| 8 | **상태** | 칩 다중선택: 미사용 정척 / 절단 잔재(4m 이상) / 녹 발생 / 장기 야적 / 잘 모름 | — | 매입 기준(4m 이상·3.5m 이하 제외)을 칩 옆 한 줄로 |
| 9 | **반출 희망** | 칩 단일: 바로 / 1주 내 / 1개월 내 / 미정 | — | 배차 우선순위 |
| 10 | 문의 내용 | textarea | — | 현행 |
| 11 | 동의 | ☑ **개인정보 수집·이용 동의(필수)** — "문의 응대 목적, 연락처·사진, 1년 보관" / ☐ **단가·시세 안내 문자 수신(선택)** | 필수 1 | 선택 동의가 어드민 문자 동의 가드(`recipientPhoneConsent`)의 근거가 된다 |
| 12 | 보내기 | "사진 n장과 함께 매입 문의 보내기" | | 업로드 중 진행 표시("사진 올리는 중 2/4") |

납품 문의는 2·6·7·8·9 를 **품목(철근/H빔/각관/C형강/기타)·규격·수량·납품 희망일** 로 바꾼다. 사진 칸은 선택으로 유지(도면·현장 사진).

### 3.2 보이지 않는 칸 (유입 캡처)

폼 로드 시 JS 로 채워 hidden 으로 보낸다: `utm_source/medium/campaign`, `referrer`(호스트만), `landing_path`, `qr_src`(`/q?src=` 에서 왔으면), `page_type`(매입/납품 섹션 어디서 눌렀나). 어드민 `lead_source` 매핑은 P2: referrer 가 `blog.naver.com` → `blog`, `m.place.naver.com`/`map.naver.com` → `naver_place`, utm_medium=cpc → `ad`, qr_src 있음 → `other`(메모 "명함 QR"), 그 외 → `homepage`.

### 3.3 성공 화면

"접수됐습니다. **영업시간(평일 8~18시) 안에는 1시간 내** 연락드립니다." + 대표 전화 `tel:` 버튼 + "급하시면 사진을 문자로도 보내 주세요" `sms:` 링크(본문에 접수번호). 카카오 채널 버튼은 [미결 1].

## 6. 어드민 전달 (P2 = 0080, 이 repo)

- 홈페이지 서버 액션이 insert·알림 뒤 `POST https://admin.<도메인>/api/public/inquiry` (헤더 `x-inquiry-secret`) 로 `{source_ref: inquiries.id, kind, name, phone, location, qty, spec, conditions, timing, message, consent_marketing, source, photos: [7일 서명 URL]}` 전달. 응답 200 이면 `forwarded_at` 기록, 실패는 로그만(재시도는 관리자 상세의 [어드민으로 다시 보내기] 버튼).
- 어드민: `web_inquiry` 테이블(`source_ref` UNIQUE 로 중복 방지, **book 없음**) + 사진은 서명 URL 에서 받아 어드민 `attachments` 버킷에 재업로드(`attachment` entity_type `web_inquiry`, 0035 CHECK 확장). `/inquiries` 공유 메뉴 목록 → **[매입견적서 작성]** 이 `PurchaseQuoteDialog` 를 `defaults`(prospect_name·site_name·lead_source(§3.2 매핑)·lead_note=규격·수량 요약·연락처)로 연다. 저장 시 `web_inquiry.status='quoted'`, `purchase_quote_id` 연결. 사진은 견적 상세 옆에 그대로 보여 통화 중 참고.
- 어드민 쪽 카카오워크 알림(기존 `notifyKakaoWork`)은 어드민 이벤트 전용으로 두고, 웹 문의 수신 알림은 홈페이지 메일로 끝낸다(중복 방지). 접수 문자(§5 [미결 2])는 여기서.
- 홈페이지 `/admin/inquiries` 는 당분간 유지(접수 원본 확인용). 어드민 쪽이 안정되면 홈페이지 관리자 로그인 없이도 되게 **홈페이지 상세에 "어드민에서 열기" 링크**만 남긴다 [미결 3].
