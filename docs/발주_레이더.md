### 기획안 대비 구현에서 달라진 점

- **[기록] = 전용 다이얼로그**(`app/radar/touch-dialog.tsx`) + RPC 직접 호출. 기획안의 'SalesLogPrefill 재사용'은 택하지 않았다 —
  결과를 자유 텍스트가 아닌 4종 라디오로 고정(D10 판정 입력)하고 책 선택이 필요 없어서. 영업내역 페이지 폼은 그대로다(2주차 [견적]·[거래처로] prefill 은 별도).
- `radar_touch` 파라미터 9개 = 기획안 7개 + `p_company`(표지판 시공사 → prospect_name) + `p_contacted_on`. 0070·0071 에서
  **수신거부 서버 강제**(행·계정에 '거절' 제외 또는 영업내역 '거절' 기록 — 수기·soft delete 무관 — 이 있으면 새 기록 거부,
  '거절'은 복구 가능 사유를 영구로 승격, 제외할 행이 없으면 오류로 거짓 성공 방지), **다음 행동일 기본 접촉일 + 7일**,
  전화 숫자만 저장, **PUBLIC·anon 실행 권한 회수**를 더했다.
- **수신거부는 화면 밖 기록에도 적용** — CSV 콜 캠페인에서 영업내역에 적은 결과를 정규화(`normalizeResultCode`)해
  ① 전화 CSV 에서 그 계정을 즉시 숨기고(거절은 이력 어디든, 연락 불가는 최신 기록일 때) ② 수기 기록 연결 때 계정 단위 제외 처리한다.
  [복구]·`radar_touch` 도 영업내역 '거절'(연결 전 메모 포함)이 있는 행·계정은 거부. 정규화 규칙: 4코드 정확 일치 우선 →
  거절·거부·연락 말라 = 수신거부(부정·번복 '거절 안 함'·'거절했다가' 제외) → 부재·재통화·통화중 = 다음에 → 견적 → 현장 없음·폐업·결번 = 연락 불가.
- **견적 문자 가드의 ★ 거래처 판정은 '레이더 연결 + 매출 없음' 기준**(거래처 출처 컬럼 없이) — 레이더 이전부터 있던 거래처라도
  매출이 없고 사업자번호로 ★ 연결되면 '견적 요청' 기록이 있어야 문자가 나간다(보수적). 정확히 가르려면 거래처 출처 컬럼
  (`partner.source_project_id`, [거래처로]로 새로 만든 거래처만 표시) 마이그레이션이 필요한데 아직 적용하지 않았다.
  가드의 거절 판정도 정규화보다 보수적이다(거절·거부·필요 없음 문구가 있으면 번복 표현이어도 차단 — 문구를 고치면 풀림).
- **단계 반영 시각 트리거(0071, 기획안 '트리거 0'의 예외)** — stage 가 바뀌는데 stage_changed_at 을 안 주는 수집기(구 코드)에도 now() 기록.
  상태 기계가 아니라 데이터 무결성용 1개.
- **`last_seen_at` 컬럼 추가(0070)** — 수집기만 쓰는 '마지막 수집 시각'. 헤더 '동기화'를 max(updated_at)로 근사하면 [제외]·정리·마이그레이션 UPDATE 에도 흔들렸다.
  1회 백필은 0069 직전 측정치(건축 10-04 09:48 KST · 나라장터 10-06 10:49 KST) 기준 근사.
- **`stage_changed_at` 기본값 now()(0070) + 갱신 트리거(0071)** — 구 수집기로 들어오거나 바뀐 행도 방문 창에 들어온다. 화면도 `stage_changed_at ?? created_at` 으로 판정.
- **RC 여부는 저장된 `usage` 가 아니라 읽는 시점 계산**(`phoneRuleMatch` 가 제목·공사종류로 `naraLabel`). `usage` 는 표시용.
- **데이터 로더 단일화** — `lib/radar/radar-data.ts`(`loadVisitRows`·`loadPhoneAccounts`·`lastSeenBySource`·`linkSalesLogNotes`)를
  화면·알림·CSV·측정·정리 검증이 같이 쓴다. 알림의 '오늘 방문 N' = 화면 '오늘' 칩.
- **수기 기록 연결 자동화** — 영업내역 메모의 "레이더 {id}"(첫 UUID) → `sales_log.project_id` 를 수집 cron 이 매일 연결(멱등). 결과가 '거절'·'현장 없음'이면 제외 처리까지.
- **수집 실패 처리** — 창·법정동 단위 오류를 모아, 실행한 소스가 0건이면 종료코드 1(cron 빨간불) + 카카오워크 경고. `RADAR_REGIONS`·`RADAR_SOURCES` 오타는 즉시 실패.
- **권역 판정 보강**(`nara-rules.ts`) — 타지역 지명은 경계 매칭('공영주차장'⊃영주·'하동소하천'⊃하동 오판 제거), 권역 지자체 발주는 제목 토큰보다 우선,
  붙여 쓴 포항 기관명(경상북도포항교육지원청·서포항농협·폴리텍대학포항) 인식, 감포→경주. 비공사 컷 예외: 임대주택·설계·시공 일괄.
- **비철근 작업 라벨** — v1 이 수집 단계에서 자르던 작업(숲가꾸기·포장·준설·지장물 철거 등)을 v2 는 남기므로 `non_steel` 로 분류해 전화 목록에서 뺀다
  (45일 재수집 직후 전화 목록이 32→44계정으로 늘었던 원인; 반영 후 기획안과 같은 32계정). 시설명 안의 작업어(청소년·태권도장·수목원)는 제외.
- **정리 스크립트의 삭제 기준** = 휴리스틱(`regionSuspect`) ∧ 수집기 판정(`matchRegionV2`) 모두 거부한 행만, 사람이 제외한 행은 건드리지 않음.
  `--restore-deleted-at` 은 v2 정리 시각(2026-10-06~)만 허용(7월 v1 중복 정리분 오복구 방지).
- **낙찰↔공고 조인은 전 창 통합 + 낙찰→공고 역행 금지**. 공고가 창 밖인 낙찰은 DB 기존 공고 행의 현장지역으로 판정.
- 읍면동 추출이 2글자 이름(서면·평동·마동·율동)을 놓치던 버그 수정 → 밴드가 바뀌었다(시내 동 일부가 중거리 → 근거리).

## 화면 — `/radar` (book 밖 독립 라우트)

축 2개: **탭**(🚗 방문 | 📞 전화) × **상태 칩**(오늘 | 대기 | 완료). 상단 숫자는 "오늘 N" 하나.

- **방문 탭** 행 = 경주 민간 현장 주소 1행. 거리 밴드(근거리=시내 동·현곡·내남·건천·천북 / 중거리=안강·외동·강동·서면 /
  원거리=양남·문무대왕·산내)로 그룹, 밴드 안은 착공 → '착공 전(허가)'(접힘) 순.
- 행 필드 ≤6: 단계·N일째·주소(+제목 힌트) / 주용도·연면적·신축/증축 / 누구(기본 "미상 → 표지판 확인", 기록 뒤 담당자·전화) /
  마지막 기록·다음 행동일. 펼침: 반영일·허가일·착공일·읍면동·기록 이력·[지도 검색](카카오맵 검색 링크, 키 불필요).
- **상태는 저장하지 않는다**(`lib/radar/v2-rules.ts deriveStatus`, 최신 기록 기준):
  - 오늘 = 미접촉 ∨ 다음 행동일 ≤ 오늘(비어 있으면 접촉일 + 7일) ∨ 기록 뒤 단계 변경 ∨ 최신 기록이 연락 불가인데 제외 안 됨([복구]한 행)
  - 대기 = 다음 행동일 > 오늘
  - 완료 = 제외(dismissed_at) ∨ 최신 기록이 거절(제외 처리 전이어도)
  - 미접촉 행은 **단계 반영일(stage_changed_at, 없으면 최초 수집) 60일** 창 밖이면 자동 이탈.
- **[방문 기록]** = RPC `radar_touch`: sales_log INSERT(결과 코드 4종 고정: 견적 요청 · 다음에 · 철근 안 씀·거절 · 현장 없음·연락 불가·폐업)
  + 제외 코드면 dismissed_at 를 한 트랜잭션으로. 다음 행동일 기본 +7일.
  **[제외]** 사유 3종(철근 안 씀·거절 / 현장 없음·연락 불가·폐업 / 기타). '철근 안 씀·거절'은 기존 제외도 영구로 승격.
  **[복구]** 는 영구 거절·영업내역 '거절' 기록이 있는 행·계정은 불가(수신거부 보장), 반영 60일이 지난 미접촉 행도 불가(복구해도 목록에 안 남음).
- **펼침 → [견적]·[거래처로]**(2주차):
  - [견적] = 기존 견적 폼(책 선택 저장)을 현장명=주소, 거래처=연결된 거래처 ∨ 방문 기록에서 확보한 업체명으로 열고, 저장 시 `quote.source_project_id`(0073)에 이 행을 남긴다.
  - [거래처로] = 기존 거래처 폼을 업체명·담당자 전화·업종(건설업)·메모(현장 주소)로 열고, 저장하면 이 행(낙찰이면 같은 사업자번호 계정)에 연결 → 카드에 ★ 거래처 표시.
    같은 사업자번호, 또는 같은 이름((주)·주식회사·공백 무시)에 사업자번호가 충돌하지 않는 거래처가 이미 있으면 **새로 만들지 않고 그 거래처에 연결**한다(마스터 중복 방지). 이미 다른 거래처에 연결된 행은 덮지 않고 알린다.
  - **견적 문자(MMS) 가드**(`sendQuoteMms` 서버 강제, `quoteMmsConsent`): 레이더에서 나온 상대는 '견적 요청' 기록이 있어야 발송, '거절' 기록·제외면 차단.
    - 대상 = 레이더 출처 견적(레이더 카드·**영업내역 행 [견적]** — 행의 project_id, 없으면 메모의 "레이더 {id}") + 출처 없이 만든 견적이라도 거래처가 레이더 행에 ★ 연결돼 있으면 그 행들.
    - 통과 = 거래처에 매출 이력이 있음(거래관계) 또는 레이더와 무관한 견적.
    - 동의는 결과가 정확히 '견적 요청'(괄호 메모 허용)일 때만. 자유 텍스트 '견적 필요 없음'·'견적서 발송'은 동의가 아니고, 거절·거부·필요 없음·수신거부 류는 보수적으로 거절로 본다.
- **★ 자동 연결**: 사업자번호가 같은 거래처를 낙찰 행에 연결 — 매일 수집 후, 거래처 저장·수정 시(사업자번호 입력) 즉시.
  거래처 삭제·사업자번호 변경 시 그 거래처(이전 번호)에 걸린 ★를 풀고 같은 번호의 다른 거래처로 다시 연결. 매일 동기화는 삭제된 거래처의 ★부터 푼다. 화면은 삭제된 거래처를 미연결로 본다.
- **영업내역 '레이더' 링크**: 레이더에서 온 기록(project_id)에 배지 → `/radar?focus={id}` 로 그 행의 칩을 열고 펼쳐 강조.
- 전화 탭(판정 전): CSV 안내만. 낙찰사 행에는 **문자·MMS 버튼을 두지 않는다**(기획안 §12 연락 채널 방침).

## 데이터 모델 — `construction_project` + v2 컬럼(0069~0073)

0038 컬럼에 더해:
- `dismissed_at`·`dismiss_reason`(CHECK 3종) — 사람의 처분. 계정(사업자번호) 단위 제외·복구·숨김은 soft delete 행까지 같은 범위.
- `stage_changed_at` — 단계 반영 시각. v2 수집기가 채우고, DEFAULT now()(0070)·**갱신 트리거 `trg_cproj_stage_changed`(0071)** 가 구 수집기도 보정. 1회 백필은 GREATEST(created_at, stage_date) 근사.
- `last_seen_at`(0070) — 수집기만 쓰는 마지막 수집 시각(헤더 '동기화').
- `awardee_bizno` — raw.bidwinnrBizno 숫자만, **생성 컬럼**(partner.business_no 조인·계정 단위 제외). 없으면 계정 키 = 행 id.
- `sales_log.project_id`(FK)·`sales_log.contact_phone`(숫자만).
- `quote.source_project_id`(0073, FK) — 레이더 [견적]의 출처. `create_quote_with_lines` 가 같은 트랜잭션에 기록. 문자 가드·레이더 유래 매출(`sale.source_quote_id` → 이 컬럼) 집계용.

- 점수 컬럼(relevance_*·est_rebar_ton)·lat/lng는 **남겨두되 null 기록**(DROP 안 함).

- 목적: 철근·강재 영업(공급 제안) 내부용. 외부 공유·재배포 없음. 소프트 삭제·제외 행도 DB에 남지만 화면에는 안 나온다.
- 연락 채널: 레이더 번호에는 **음성 통화만**(첫 문장 "나라장터 낙찰 정보(공공데이터)를 보고 연락드린 경주 ○○철강입니다").

- 보관: CSV 내보내기 파일(`radar-v2-*.csv`)은 개인정보 포함이라 커밋 금지(gitignore), 사용 후 삭제.

## 사람이 직접 해야 할 것

1. **D0 콜·방문 시작**: `npm run radar:v2:export` → 전화 담당 1명 하루 30분(≈10콜), 방문은 배달 동선에 근거리 밴드부터 하루 2곳.
   전화 기록은 `/all/sales-log`(잠재 거래처명=낙찰사, 채널=전화, 결과=4코드 문자열, 메모 첫 줄에 CSV 마지막 열 "레이더 {id}" 그대로 붙여넣기).
   '거절'을 적은 계정은 다음 CSV 에서 즉시 빠지고, 수집 cron(또는 정리 스크립트)이 project_id 연결·계정 제외까지 처리. **방문 기록은 화면 [방문 기록]으로만.**
2. **전국건설업체정보 API 활용신청**(data.go.kr 15061362 키스콘 건설업체정보, 자동승인) → 승인 당일 `npm run radar:v2:kiscon` 으로 마스킹 계정 전화 채움률 측정(≥70%면 마스킹 행 복귀).
3. **D10 판정**(2026-10-21 무렵): `npm run radar:v2:judge` — 견적 요청 계정 ≥3 → 전화 탭 구현 / 2 → 2주 연장 / 0~1 → A규칙(경주 소재 낙찰사) 폐기, ★·RC만.
   방문은 '현장 없음' 비율·담당자 확보율로 표지판 가정 판정, 단독주택 60~150㎡ 행의 제외율로 하한 재조정.
   견적은 레이더 카드나 영업내역 행의 [견적]으로 만들어야 출처가 남아 '레이더 유래 매출'로 집계된다(견적 메뉴에서 새로 만들면 안 잡힘).
   판정 스크립트는 ★ 연결 거래처의 캠페인 기간 매출도 '참고'로 보여주지만, 기존 거래처 매출이 섞일 수 있어 판정에는 넣지 않는다.
4. 4주 말: 레이더 유래 매출 ≥1 아니면 A규칙 축소 확정. 민간 동기화 "신규·단계변경 행 수"로 주기 재검토.
