## 1. 한 줄 결론

0075로 "전화 받고 kg당 단가를 적어 문자로 보내는" 1단계는 끝났다 [확인]. v1.1은 **0078 마이그레이션 1개**로 (a) 계근 후 **라인별 실중량만 넣고 매입을 원자적으로 만드는 RPC** `convert_purchase_quote_to_purchase`(기존 `create_purchase_with_lines` 래핑, 매입 CHECK 전부 상속), (b) 한 견적 → **여러 차수 매입** 추적(`purchase.source_purchase_quote_id`), (c) 판매자 연락처·예상중량 컬럼, (d) B계좌 단가 감사 트리거를 더하고, 앱에서는 전환 다이얼로그·'저장 후 문자'·복제·유효기간 가드·문자 본문 단가 병기·매입 전용 문자 동의 함수를 붙인다. 기존 `quote` 모듈·`purchases/actions.ts createPurchase` 동작은 바꾸지 않는다(창고 해석 블록만 함수로 추출).

## 3. 원칙

1. **견적은 단가표, 매입은 계근표.** 견적 테이블에 중량·총액을 절대 두지 않는다. 총액이 생기는 유일한 지점은 전환 RPC 안의 `line_subtotal = round(price_per_kg × 정산중량)` 이다(도메인 룰 v1 §6.2: kg 매입 = `price_basis='actual'`, `actual_weight_kg` 필수).
2. **기존 RPC를 감싼다, 복제하지 않는다.** 전환은 `create_purchase_with_lines`(0046)를 plpgsql 안에서 호출해 `chk_kg_unit_actual_required`·`chk_bk_documented`(0043 강화판)·`chk_b_undocumented`·시세 트리거(0015)를 그대로 물려받는다.
3. **한 견적, 여러 매입.** 전환은 견적을 닫지 않는다. 닫는 것은 사람의 '마감'(`done`) 한 번이다.
4. **거래처 마스터는 전환 시점에 확정**(절대 룰 3). 견적 단계 prospect 자유 텍스트는 유지, 전환에서 `resolvePartnerId` 자동 생성을 쓰지 않고 datalist 선택을 강제한다.
5. **매출 견적 코드는 건드리지 않는다.** `quote*`·`radar-data.ts` 기존 함수·`globals.css`·`lib/transaction-draft.ts` 변경 0.

## 4. 데이터 — `supabase/migrations/0078_purchase_quote_convert.sql` (신규)

(레포 최신 0075 [확인]. 신규 테이블 0 · 컬럼 4 · 인덱스 1 · RPC 1 신규 + 1 재정의 · 트리거 2 · RLS 변경 0.)

```sql
-- (a) 헤더·라인 보강
ALTER TABLE purchase_quote
  ADD COLUMN IF NOT EXISTS contact_phone TEXT;              -- 통화 중 받은 판매자 번호. 문자 기본 수신(partner.phone 보다 우선)
ALTER TABLE purchase_quote_line
  ADD COLUMN IF NOT EXISTS est_weight_kg NUMERIC(12,3);     -- 예상 중량(참고). 문서 미출력, 전환 폼 placeholder

-- (b) 매입 역참조 — sale.source_quote_id(0053) 미러. 한 견적에 여러 매입(차수) 허용 → UNIQUE 아님
ALTER TABLE purchase ADD COLUMN IF NOT EXISTS source_purchase_quote_id UUID REFERENCES purchase_quote(id);
CREATE INDEX IF NOT EXISTS idx_purchase_source_pq ON purchase(source_purchase_quote_id) WHERE source_purchase_quote_id IS NOT NULL;

-- (c) 감사 — 0068 패턴. book 컬럼이 있으므로 audit_trigger_fn 이 b 책 row 를 sensitive=TRUE 로 남긴다(절대 룰 2)
DROP TRIGGER IF EXISTS trg_audit_purchase_quote ON purchase_quote;
CREATE TRIGGER trg_audit_purchase_quote AFTER INSERT OR UPDATE OR DELETE ON purchase_quote FOR EACH ROW EXECUTE FUNCTION audit_trigger_fn();
DROP TRIGGER IF EXISTS trg_audit_purchase_quote_line ON purchase_quote_line;
CREATE TRIGGER trg_audit_purchase_quote_line AFTER INSERT OR UPDATE OR DELETE ON purchase_quote_line FOR EACH ROW EXECUTE FUNCTION audit_trigger_fn();

-- (d) 전환 RPC — 계근 결과(라인별 정산중량)를 받아 매입 1건 생성. 견적 status 는 바꾸지 않는다(차수 반복 허용).
CREATE OR REPLACE FUNCTION convert_purchase_quote_to_purchase(p_quote_id uuid, p_purchase jsonb, p_lines jsonb)
RETURNS uuid LANGUAGE plpgsql SECURITY INVOKER SET search_path = public AS $$
DECLARE v_q purchase_quote%ROWTYPE; v_pid uuid;
BEGIN
  SELECT * INTO v_q FROM purchase_quote WHERE id = p_quote_id AND deleted_at IS NULL FOR UPDATE;
  IF NOT FOUND THEN RAISE EXCEPTION '매입견적을 찾을 수 없습니다'; END IF;
  IF v_q.status = 'done' THEN RAISE EXCEPTION '마감된 매입견적입니다 — 마감을 풀거나 새 견적을 작성하세요'; END IF;
  IF (p_purchase->>'book')::book_type <> v_q.book THEN RAISE EXCEPTION '매입 책이 견적 책과 다릅니다'; END IF;
  IF COALESCE((p_purchase->>'is_documented')::boolean, TRUE) <> v_q.is_documented THEN
    RAISE EXCEPTION '자료/무자료 구분이 견적과 다릅니다';
  END IF;
  v_pid := create_purchase_with_lines(p_purchase, p_lines);        -- 0046 재사용: purchase CHECK·시세 트리거 그대로
  UPDATE purchase SET source_purchase_quote_id = p_quote_id WHERE id = v_pid;
  UPDATE purchase_quote SET status = 'sent', sent_on = COALESCE(sent_on, CURRENT_DATE)
    WHERE id = p_quote_id AND status = 'draft';                     -- 전환됐으면 최소 '발송' 이상
  RETURN v_pid;
END $$;
GRANT EXECUTE ON FUNCTION convert_purchase_quote_to_purchase(uuid, jsonb, jsonb) TO authenticated;

-- (e) update_purchase_quote_with_lines 재정의(0075 본문 전체 복사 + 가드 2줄 + contact_phone·est_weight_kg)
--   IF EXISTS (SELECT 1 FROM purchase WHERE source_purchase_quote_id = p_quote_id AND deleted_at IS NULL)
--      THEN RAISE EXCEPTION '이미 매입으로 전환된 견적은 단가·품목을 수정할 수 없습니다(새 견적으로 복제하세요)'; END IF;
--   status='done' 도 RAISE. quote 모듈의 "won 이후 수정" 구멍을 여기서는 막는다.
-- (f) create_purchase_quote_with_lines 재정의 — contact_phone·est_weight_kg 추가. NOTIFY pgrst, 'reload schema';
```

[결정] status enum 은 0075의 `done`(라벨 '매입완료' → **'마감'** 으로 라벨만 변경)을 유지한다. 설계안 2의 `converted` 로 바꾸려면 `ALTER TYPE … RENAME VALUE` 가 필요하고 의미도 "전환됨"이 아니라 "닫힘"이 맞다(차수 반복 허용 때문).
[결정] 톤당 단가 GENERATED 컬럼(설계안 2·3)은 두지 않는다 — 0075가 `perKgToPerTon`(×1,000) 앱 계산으로 목록·문서·상세를 이미 통일했고 [확인], SQL 조회 수요가 없다.
[결정→반영] doc_no 채번은 **0076 에서 DB 로 이동**(`next_purchase_quote_doc_no(date)`, SECURITY DEFINER + advisory lock, soft-delete 행 포함 MAX+1). 앱의 count 채번은 RLS 가시 범위만 세어 책 권한이 제한된 사용자에게 UNIQUE 충돌이 났기 때문(리뷰 확정). `.is('deleted_at', null)` 필터는 쓰지 않는다 — soft-delete 행도 UNIQUE 를 점유한다 [확인 0075 DDL].

## 13. 사용자 결정 필요 사항

1. **법인(bk)이 개인·비사업자에게 고철을 사는 경우** — 현재 룰(0043)로는 자료 종류가 없어 전환이 막힌다. 기본 제안: **사업자(sl) 책으로 유도**(폼 힌트). 매입자발행세금계산서·원천징수 경로는 세무사 확인 후 별도.
2. **B계좌 매입견적서의 외부 발송·공유** — MMS 발송은 허용하되 카카오워크 운영방에는 **텍스트만**(단가·이미지 없음) 공유. 기본: 채택.
3. **한 견적 → 여러 차수 매입** 허용, 견적 닫기는 수동 '마감'. 기본: 예(전환이 견적 상태를 바꾸지 않음).
4. **문서 부가세 표기** — `단가 = 공급가액, 부가세 별도` 단일 모드 유지(포함가 열 없음). 기본: 유지.
5. **공제(토사·이물)** — 전환 다이얼로그에서 라인별 공제 kg 를 받아 `정산 = 계근 − 공제` 로 금액 계산하고 `purchase_line.notes` 에 남긴다. 기본: 채택(공제 0 이면 계근 그대로).

## 14. 리스크·미확인 가정

- **`PurchaseFormDialog` 가 아닌 별도 전환 다이얼로그**라 매입 폼의 검증(가닥수·이론중량)을 공유하지 않는다 — kg 단위만 다루므로 `chk_bars_count_required` 와 무관 [확인 0008], DB CHECK 가 최종 방어.
- **`resolveDefaultWarehouse` 추출**은 운영 중인 `createPurchase` 를 건드린다(동작 동일 의도). PR-3 에서 매입 등록 회귀를 반드시 확인.
- **`convert_purchase_quote_to_purchase` 가 `create_purchase_with_lines` 를 호출**: 둘 다 SECURITY INVOKER 라 RLS 는 호출자 기준 [확인] — staff 권한이면 purchase INSERT 가능. `FOR UPDATE` 로 동시 전환 직렬화.
- **`recipientPhoneConsent` 의 sale 전용 조회는 그대로 둔다**(기존 매출 견적 동작 보존). 새 함수가 purchase 이력을 먼저 보므로 매입 상대는 걸리지 않지만, 레이더 번호 + 이력 0 인 판매자는 여전히 '견적 요청' 기록이 있어야 한다 — 상대가 먼저 전화한 사실은 운영자가 `contact_phone` 을 입력한 것으로 간주 [추측].
- **zoom 표시 + 캡처 전 복원**은 `html2canvas-pro` 와 `zoom` CSS 의 상호작용을 실측하지 않았다 [추측]. 실패 시 캡처용 숨김 노드(화면 밖 800px) 로 대체.
- **`navigator.share` 파일 공유**는 iOS Safari·Android Chrome 만 지원 — 미지원 브라우저는 버튼 숨김.
- **partner 에 매출처/매입처 구분이 없고 `name` 이 UNIQUE 가 아니다** [확인 0004]. 전환 datalist 에 매출처가 섞이고 동명 거래처가 있으면 첫 건을 집는다 — 전환 폼에서 선택 시 `representative`·`phone` 을 함께 보여 구분. 구분 컬럼은 거래처 마스터 과제로 분리.
- **audit 트리거는 `audit_trigger_fn()` 이 `book` 컬럼을 읽어 sensitive 를 정한다** [확인 0017 78행] — purchase_quote 에 book 이 있으므로 추가 설정 없음. 단 트리거가 UPDATE 마다 before/after JSON 을 쌓아 `update_purchase_quote_with_lines` 의 라인 delete→insert 가 라인 수 ×2 행을 남긴다(감수).
- **견적 `is_documented` 와 매입 자료성 일치 검사**를 RPC 에 넣었다 — sl 책에서 견적은 자료, 실제는 무자료로 바뀌는 경우 전환이 거부된다. 그때는 견적을 복제해 무자료로 다시 작성(의도된 보수).
- **시세 트리거 발화**: 전환이 `delivered_on` 을 채우지만 `item.market_item_id` NULL 이라 no-op [확인]. 추후 market_item 연결을 결정하면 이 전환 경로가 고철 시세의 첫 데이터 소스가 된다.
- **0075~0077 이 이미 배포된 DB 에 0078 을 적용**: 기존 `purchase_quote` 행의 `contact_phone`·`est_weight_kg` 는 NULL, 상태값 변경 없음 — 백필 불필요.
