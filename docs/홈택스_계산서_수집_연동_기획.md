# 홈택스 계산서 수집 연동 기획 — 매출은 대사, 매입은 역생성

> **문서 성격**: 2026-10-24 기획. 팝빌 "홈택스 전자(세금)계산서 연계"(정액제, 사업자번호당 월 33,000원 — 사장 확인)로 국세청에 있는 매출·매입 계산서를 우리 시스템으로 가져와, **매출은 시스템 기록과 맞추고(대사), 매입은 계산서로부터 거꾸로 매입 데이터를 만든다(역생성)**.
> 표기: **[확인]** 코드·DB에서 검증 · **[결정]** 이 안의 선택 · **[미결]** 사장 결정 필요.

---

## 0. 한 줄 결론 [결정 2026-10-24]

팝빌 정액제(사업자 sl 1개부터)로 홈택스의 **매출·매입 계산서를 전부 가져와** 별도 테이블(`hometax_invoice`, 승인번호 유일키)에 쌓는다. **매출은 시스템 매출과 맞추고(대사)**, **매입은 직접 입력 대신 수집본으로 매입을 채워 넣고 사장이 수정하는 것을 기본 흐름**으로 한다. 시스템은 수집본을 흉내 내지 않고 거래와 **연결(link)** 만 하며, 자동으로 거래를 만들거나 고치지 않는다 — 프리필 → 사람이 확인·저장.

## 1. 왜 필요한가 — 지금 구멍 [확인]

매출 세금계산서가 시스템에 들어오는 경로가 둘인데 하나가 비어 있다.

| 경로 | 시스템에 남는 것 | 구멍 |
|---|---|---|
| ① 시스템 → 팝빌 발행 | `tax_invoice(provider='popbill')`, 승인번호 자동 수신, 상태 조회 가능 | 없음 |
| ② 홈택스에서 직접 발행 후 **[수기 기록]** | `tax_invoice(provider='manual', mgt_key='manual-{book}-{doc_no}')`, 번호는 **사람이 입력** | 승인번호 오타·누락, 금액 검증 없음, 원본 PDF 없음 |
| ③ 홈택스에서 발행했는데 시스템에 매출 자체가 없음 | 아무것도 없음 | **매출 누락** — 부가세 신고 때 홈택스 합계와 시스템 합계가 안 맞는 원인 |

매입 쪽은 더 비어 있다. `purchase.tax_doc_type`·`tax_doc_no` 칸만 있고 **받은 계산서 데이터 자체가 없다**. 거래처가 끊어 준 계산서를 보고 사람이 매입을 치는 구조라, 빠지거나 금액이 다른 걸 잡을 방법이 없다.

홈택스에는 ①②③ 과 매입이 **전부, 승인된 금액으로** 있다. 그래서 수집본을 기준으로 삼는다.

## 2. 원칙 [결정]

1. **수집본이 진실.** 시스템 기록과 다르면 수집본이 맞고, 시스템 쪽을 고친다(단, 자동 수정은 안 하고 '불일치'로 띄운다).
2. **한 테이블, 두 방향.** 매출(SELL)·매입(BUY)을 `hometax_invoice` 한 곳에 `direction` 으로 구분. 승인번호(`nts_confirm_num`) UNIQUE 로 중복 수집·역발행 중복(우리가 역발행 요청한 매입 계산서는 발행 API 에도 보임)을 막는다.
3. **연결만 한다.** 거래 테이블(`sale`·`purchase`·`tax_invoice`)은 기존 RPC 로만 쓴다. 수집본 행에 `sale_id` / `purchase_id` / `tax_invoice_id` 와 `match_status` 를 둔다. **매입은 수집본이 입력의 출발점**이지만, 저장은 사람이 프리필 폼을 확인한 뒤 누른다(자동 생성 없음 — 재고·미지급에 바로 영향).
4. **책 = 수집한 사업자번호.** 법인(bk)·사업자(sl) 각각의 사업자번호로 수집하므로 수집본의 책은 자동으로 정해진다. **B계좌(b)는 대상이 아니다**(무자료 — 절대 룰 2). 정액제는 사업자번호당이므로 둘 다 하면 2개 [미결 1].
5. **주 입구는 팝빌 정액제 수집.** [결정 2026-10-24] 팝빌이 홈택스에서 수집한 것을 우리가 API 로 가져온다. 홈택스 엑셀 업로드는 **보조·후순위**(수집이 막혔을 때 대비)로 테이블 구조만 호환되게 둔다.

## 2.5 수집 범위 [결정 2026-10-24]

| 항목 | 결정 | 비고 |
|---|---|---|
| 사업자번호 | **사업자(sl, 신라철강) 정액제 1개로 시작** | 법인(bk)은 거래가 늘면 정액제 추가. 테이블·크론·화면은 처음부터 책별 |
| 방향 | 매출(SELL) + 매입(BUY) | 매출은 대사, 매입은 역생성 |
| 소급 | 2026-05(운영 시작) 이후 전부 1회 | 그 전 기간은 받아도 '시스템에 없는 매출'로만 쌓이므로 제외 |
| 주기 | 매일 06:00 KST 1회 + [지금 수집](기간 지정) | 기준일 = 전송일(S), 최근 7일. 승인번호 UNIQUE 로 중복 제거 |
| 인증 | 홈택스 **부서사용자** ID 를 팝빌에 등록(`registDeptUser`) | 공동인증서 갱신 부담 없음. 비밀번호는 팝빌에만 두고 우리 DB 에 저장 안 함 |
| 면세 계산서 | 같이 수집, 같은 화면에 '계산서' 배지 | 거래처에 따라 섞일 수 있음 |

## 3. 매출 방향 — 대사(照合)

### 3.1 매칭 규칙 [결정 2026-10-24]

| 순위 | 규칙 | 결과 |
|---|---|---|
| ① | 승인번호 일치 — `tax_invoice.nts_confirm_num`(팝빌 발행 수신분·수기 입력분) | **자동 '일치'** |
| ② | 받는자 사업자번호 = `partner.business_no` + 작성일 = 발행 기록 `write_date`(없으면 매출 납품일) + 합계금액 = 매출 총액, **완전 일치** | **자동 '일치'** (번호 없이도 확실) |
| ③ | 사업자번호 + 금액 일치, 작성일 ±3일 | **'후보'** — 1클릭 확정(같은 거래처·같은 금액 두 건 가능성) |
| — | 어디에도 없음 | **홈택스에만 있는 매출** → **[매출 생성] 프리필로 시스템에 넣는다**(거래처·납품일=작성일·자료거래·금액 라인은 철제 직접입력(STEEL_CUSTOM)·발행 기록 `source='hometax'` 자동 연결). 중량 라인은 사람이(매입과 같은 원칙) |
| — | 시스템엔 발행 표시인데 홈택스에 없음 | 발행 후 **3일** 지나도 수집 안 되면 **'미전송 경고'**(팝빌 전송 실패·수기 오기록) |
| — | 승인번호 같고 금액 다름 | **'불일치'** 표시만. 자동 수정 없음(시스템 매출 수정 vs 수정세금계산서 발행은 건별 판단) |

- **수기 기록(`provider='manual'`) 건**: 수집본으로 **승격** — 승인번호·금액·작성일을 수집본 값으로 덮고 출처를 '홈택스 확인'으로. 입력 번호가 틀렸으면 ②로 잡아 후보 제시.
- **무자료 매출 제외**: sl 책 안에서도 `is_documented=false` 건은 비교 모수에서 뺀다(B계좌 책은 애초에 대상 아님).

### 3.2 수정세금계산서·불일치 처리 [결정 2026-10-24]

전제 [확인]: 시스템에는 **발행 취소**(전송 전)만 있고 **수정세금계산서 발행 기능이 없다**. 수정분은 홈택스에서 직접 끊고 수집본으로만 들어온다(시스템 수정발행은 별도 과제).

| 항목 | 결정 |
|---|---|
| 수정분 묶기 | 수집본에 `modify_code`·`orig_nts_confirm_num` 저장. 당초 + 수정분(여러 장)을 **한 그룹**으로 보여 주고 그룹 **순합계**가 유효 금액(착오정정 = (-)당초 + (+)정정 2장 / 금액변동·환입 = 차액 1장 / 이중발급 = (-) 1장) |
| 대사 기준 | 매출·매입 모두 **그룹 순합계 vs 시스템 금액**. 대사표 합계도 순합계 |
| 수정분 도착 | 당초에 연결된 매출/매입에 **'수정분 있음 · 차액 ±금액' 배지**. 전액 (-)면 '취소됨' 경고. **거래 금액 자동 수정 없음** |
| 금액 반영 방식 | **1차: 배지 + [매출/매입 수정으로 이동] 링크** — 사람이 기존 수정 화면에서 반영하면 불일치가 자동으로 '일치'로. 금액만 바꾸는 전용 RPC(1클릭)는 사례를 본 뒤 2차 |
| 불일치 액션 | ① 금액 불일치 → [수정으로 이동] / [수정세금계산서 필요 메모] / [무시] · ② 거래처 사업자번호 불일치(마스터 오타) → [거래처 사업자번호 갱신] · ③ 날짜만 다름 → 후보(§3.1·§4.1) · ④ 이중발급 의심(같은 거래처·금액·날짜 2장) → '수정(-) 대기' 경고 |
| 무시(ignored) | 사유 필수, 되돌리기 가능, 대사표에 별도 줄로 집계 |
| 취소된 우리 건 | 시스템 `cancelled` 인데 홈택스에 승인 상태로 남아 있으면 **'취소 안 됨' 경고**(전송 후 취소만 누른 사례) |

### 3.3 효과 — 부가세 대사표

월 선택 → **홈택스 매출 합계 · 시스템 자료거래 매출 합계 · 차이 목록(홈택스에만 / 시스템에만 / 금액 불일치)** 세 줄. 신고 전에 차이가 0 이면 그 달 준비 끝. 지금은 이 표를 만들 데이터가 없다.

## 4. 매입 방향 — 수집본으로 매입을 채운다 [결정 2026-10-24]

### 4.0 기본 흐름

**매입은 직접 입력이 아니라 수집본에서 시작한다.** 홈택스 매입 탭이 곧 "매입 대기 목록"이고, 각 건의 기본 액션이 **[매입 생성]** 이다 → 수집본 내용(매입처·작성일·금액·품목 라인·승인번호)으로 **매입 폼을 채워서 열고 → 사장이 kg 라인 등을 고친 뒤 저장**. 직접 입력(기존 매입 폼)은 계산서가 아직 안 온 급한 건에만 쓰고, 그런 건은 나중에 수집본이 오면 **[기존 매입에 연결]** 로 증빙을 붙인다.

### 4.1 규칙

매출과 다른 점 둘: 계산서는 **상대가 끊어 주는 것**이라 우리 입력과 안 맞기 쉽고, **한 달치를 한 장으로 합산**해 끊는 거래처가 많아 "계산서 1장 ↔ 매입 여러 건"이 된다.

| 항목 | 결정 |
|---|---|
| 매입처 매칭 | 공급자 사업자번호 = `partner.business_no` 만(이름 매칭 안 함). 없으면 **[거래처 등록]** 프리필(상호·대표·주소·업태·종목 — 계산서에 다 있음) |
| 기본 액션 = [매입 생성] | 수집본마다 기본 버튼. 같은 매입처에 **미증빙 매입**(자료거래인데 `tax_doc_no` 없음)이 있으면 그 옆에 **[기존 매입에 연결]** 을 함께 보여 준다(여러 건 체크 → 합계 = 계산서 금액이면 연결, 1:N). 연결 시 `purchase.tax_doc_type='tax_invoice_electronic'`, `tax_doc_no=승인번호`, 수집본 `linked` |
| 자동 확정 | 직접 입력된 매입이 있을 때만 해당: 매입처 + 합계금액 + 작성일 ±7일에 **단일 후보**면 자동 '일치'. 그 외 '후보'(월말 발행·금액 중복) |
| [매입 생성] 프리필 | 책(수집 사업자)·매입처·발주일=입고일=작성일·자료거래·전자세금계산서+승인번호·상태 **입고완료**·결제예정일 = 거래처 기본조건(없으면 작성일+30)·**라인 = 계산서 품목 그대로**(A안, 아래). 저장은 `create_purchase_with_lines`. 저장 후 수집본에 `purchase_id`, 상태 `linked` |
| **라인 처리 = A안** | 계산서 품목 라인을 **철제 직접입력(`STEEL_CUSTOM`) 금액 라인으로 그대로 채운다**(품명·규격·수량·단가·공급가액). 재고에 들어갈 **kg 라인(철근·고철)은 사장이 계근표 보고 바꾼다** — 폼 위에 "계산서 품목(참고)" 노트와 합계 일치 표시. 품목명이 마스터와 정확히 일치하면 품목만 연결(수량은 비움) |
| 중복 | 우리가 역발행 요청한 매입 계산서도 수집에 잡히지만 승인번호가 같아 한 건 |
| 무자료 매입 제외 | 계산서 없는 매입은 대사 모수에서 뺀다. 계산서를 안 끊는 거래처는 '미증빙'이 아니라 '해당 없음' → 거래처에 **무자료 거래처 플래그**(신규 컬럼) [미결 7] |
| 법인(bk) | 정액제 추가 시 같은 규칙. bk 는 자료 100% 라 '미증빙 매입' 0 이 정상 → 대사표에 경고(절대 룰 1 점검) |

## 5. 수집 메커니즘 — 팝빌 HTTaxinvoice [확인 SDK 포함]

```
requestJob(사업자번호, SELL|BUY, 기준일 S(전송일), 시작, 끝)  → jobID
getJobState(jobID) 폴링 → 완료
search(jobID, 페이지) → 목록(승인번호·작성일·공급자/받는자·금액)
getTaxinvoice(승인번호) → 상세(품목 라인·수정사유·당초번호)
```

- **크론**: 매일 06:00 KST, 사업자별 SELL + BUY, **전송일(S) 기준 최근 7일**(상대가 발행해도 홈택스 전송은 익일이라 작성일 기준이면 빠진다). 승인번호 UNIQUE 라 겹쳐 수집해도 안전.
